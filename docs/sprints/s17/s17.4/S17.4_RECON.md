## 1. Executive Summary

Sprint S17.3 technically prepared Shyam's discovery and provider layers to
propagate `flux_peer_id`, `zarya_url`, and `flux_url` across local networks.
However, end-to-end multi-device physical validation remained unproven with
concrete physical evidence. Furthermore, a deferred contract defect existed
in `ContinuityService._transfer_artifacts`: structured transfer failures
(`FluxTransferResponse.status == FAILED`) were not inspected, which could
cause false positive continuations when Flux reported a failed transfer
without raising an exception.

S17.4 exists to close both gaps: prove the physical path works between two
real machines, and surgically fix the transfer status inspection defect.

## 3. Discovered Vulnerabilities & Gaps

### 3.1 Deferred Structured Transfer Failure Defect (Section 16)

**Location:** `src/shyam/continuity/service.py`, method `_transfer_artifacts()`

**Problem:** The method executed transfers via `loop.run_in_executor()` and
extracted `transfer_id` from the result, but completely ignored
`transfer_result.status`. If Flux returned `FluxTransferStatus.FAILED` or
`FluxTransferStatus.CANCELLED` without raising an exception, the pipeline
proceeded directly to the continuation stage, reporting false success.

**Impact:** A network-level transfer failure could silently result in the
target Zarya receiving a continuation request for artifacts that were never
actually delivered.

**Fix Strategy:** Inspect `transfer_result.status` after each transfer call.
If status is `FAILED` or `CANCELLED`, immediately transition the session to
`ContinuityState.FAILED` with an explicit reason.

### 3.2 Missing Physical Evidence Schema

S17.3's validator (`tools/s17_3_physical_validator.py`) produced basic
evidence but lacked:
- Deterministic SHA-256 payload integrity calculation across source and target.
- Distinct hardware network endpoint recording (real LAN IPs, not localhost).
- Standardized `PHYSICAL_EVIDENCE.json` schema matching the S17.4 brief.

## 4. Work Plan

1. **Targeted code fix:** Patch `_transfer_artifacts()` in
   `src/shyam/continuity/service.py` to inspect `transfer_result.status`.
2. **Unit regression test:** Add test in `tests/unit/test_s16_service.py`
   verifying structured failure handling.
3. **Physical validator tool:** Create `tools/s17_4_physical_validator.py`
   with dual-role CLI (source/target), SHA-256 integrity, and evidence export.
4. **Integration test suite:** Create
   `tests/integration/test_s17_4_physical_continuity.py` with 5 test cases
   covering happy path + 4 failure scenarios using real S13 TrustService.
5. **Evidence generation:** Produce `PHYSICAL_EVIDENCE.json` artifact.
6. **Documentation:** Generate sprint reports (Recon, Test Plan, Validation,
   Completion, Post-Completion).
