## Architectural Reconnaissance & Gap Analysis

### 1. Gap Analysis Identified in Discovery Metadata
During physical runtime introspection (Block 7 & Block 8), we found that `DiscoveryService._announce_loop()` hardcoded `metadata: {}` in its UDP broadcast payload. While S17.2 introduced `flux_peer_id` and `zarya_url` onto `ContinuityTarget` and `ContinuityService._select_target` supported reading them from node/provider metadata, real physical UDP announcements were transmitting zero metadata.

### 2. Surgical Fix Implemented
- **DiscoveryService**: Added `metadata_provider: Callable[[], dict[str, Any]] | None` to allow dynamic metadata collection during periodic announcements.
- **EcosystemDiscoveryService**: Updated `ingest_udp_peer` to ingest `zarya.agent` provider and `zarya.work.continue` capability when `zarya_url` is present in remote metadata.
- **Runtime**: Configured `DiscoveryService` with `_get_discovery_metadata` hook exporting `zarya_url`, `flux_url`, and `flux_peer_id`.
- **FluxProvider**: Exposed `@property def peer_id(self) -> str | None`.
