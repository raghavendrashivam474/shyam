## 2. Progressive Validation Stages

Validation executes strictly across seven sequential checkpoints:

### Stage S17.1-A — Node Startup & Identity

- **Objective**: Boot Node A and Node B independently with valid S13 identities.
- **Verification Gate**:
    - Node A and Node B export NodeIdentityReadyEvent.
    -  Both local trust stores self-grant personal trust.
    -  Both runtimes reach LifecycleState.RUNNING.

### Stage S17.1-B — Ecosystem Discovery (S8)

- **Objective**: Verify cross-node discovery using S8 registry ingestion.
- **Verification Gate**:
    - Node A's registry contains Node B with state AVAILABLE.
    - Node B's registry contains Node A with state AVAILABLE.
    - Capabilities (zarya.work.continue, connectivity.transfer) are indexed.

### Stage S17.1-C — Mutual Trust Establishment (S13)

- **Objective**: Establish mutual cryptographic trust between Node A and Node B.
- **Verification Gate**:
    - Node A records Node B as TrustStatus.TRUSTED (relationship PEER).
    - Node B records Node A as TrustStatus.TRUSTED (relationship PEER).
    - trust_service.is_trusted() returns True symmetrically.

### Stage S17.1-D — Target Selection (S9)

- **Objective**: Verify S9 HybridNavigator selects Node B for capability zarya.work.continue.
- **Verification Gate**:
    - Navigator returns NavigationResult with selected.node_id == Node B.
    - Deterministic explanation matches constraints.

### Stage S17.1-E — Flux Artifact Transfer

- **Objective**: Transfer the test fixture file (s17_1_payload.txt) from Node A to Node B.
- **Verification Gate**:
    -FluxProvider.transfer() completes successfully.
    -Integrity checksum is verified.

### Stage S17.1-F — Zarya Work Continuation (N4)

- **Objective**: Invoke ZaryaProvider.continue_work() with the deterministic fixture.
- **Verification Gate**:
    - Response returns VerificationOutcome.VERIFIED_SUCCESS.
    - Reconstruction and execution completed flags are both True.

### Stage S17.1-G — Full E2E S16 Continuity Pipeline

- **Objective**: Execute ContinuityService.request_continuity() end-to-end without manual stitching.
- **Verification Gate**:
    - Session reaches ContinuityState.COMPLETED.
    - ContinuityResult.outcome == ContinuityOutcome.SUCCESS.
    - Artifact transfer, reconstruction, and execution are all verified.

## 4. Evidence Capture Checklist

For every validation run, the integration test harness must record:

1. `node_a_id`, `node_b_id`
2. `s13_public_key_a`, `s13_public_key_b`
3. `discovery_timestamp`, `discovery_status`
4. `s9_selected_node_id`, `s9_reason`
5. `flux_transfer_id`, `flux_status`
6. `zarya_operation_id`, `zarya_raw_outcome`
7. `continuity_id`, `continuity_final_state`, `continuity_outcome`

## 5. Architectural Non-Regression Rules

- Baseline 388 unit tests must remain 100% green.
- No mock shortcuts inside the multi-node test harness.
- Any observed mismatch between code and physical protocol must be recorded in `S17.1_VALIDATION_REPORT.md` 
  before writing an ADR or modifying production code.
