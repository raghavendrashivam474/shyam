# S17.5 TEST PLAN — Ecosystem Startup & Runtime Readiness

## Sprint
**S17.5 — Ecosystem Startup & Runtime** (Parent: S17 — V1 Convergence)

## Objectives
Validate that Shyam operates as an independent orchestrator capable of:
1. Dynamically discovering sovereign component (Zarya, Flux) readiness without supervising their processes.
2. Gracefully handling boot ordering delays (e.g., Zarya or Flux starting seconds after Shyam).
3. Correctly aggregating component states into ecosystem readiness (`STARTING`, `READY`, `DEGRADED`, `UNAVAILABLE`).
4. Publishing reactive events upon readiness state transitions.
5. Dynamically registering capabilities and provider descriptors when delayed components become available.
6. Cleanly shutting down background polling tasks without leaking resources.

---

## Test Inventory

### 1. Unit Tests (`tests/unit/test_readiness.py`)
- `test_readiness_tracker_initial_state`: Verifies initial `STARTING` state before polling.
- `test_readiness_all_ready`: Verifies that when local node, Zarya, and Flux are available, aggregate readiness is `READY`.
- `test_readiness_degraded_when_zarya_unavailable`: Verifies `DEGRADED` state when Zarya is unreachable but Flux is online.
- `test_readiness_degraded_when_flux_unavailable`: Verifies `DEGRADED` state when Flux is unreachable but Zarya is online.
- `test_delayed_component_startup_detection`: Verifies delayed provider readiness transitions from `UNAVAILABLE` to `READY` and triggers dynamic capability registration.
- `test_component_crash_and_recovery`: Verifies component degradation when a live provider fails status checks and recovers upon restoration.
- `test_readiness_events_published`: Verifies `ComponentReadinessChangedEvent` and `EcosystemReadinessChangedEvent` emission.
- `test_tracker_background_start_and_stop`: Verifies background asyncio polling task start and graceful cancellation on stop.

### 2. Integration Tests (`tests/integration/test_runtime_startup_readiness.py`)
- `test_runtime_startup_with_all_components_ready`: Tests end-to-end `ShyamRuntime` startup with all mock components online.
- `test_runtime_startup_with_delayed_components`: Tests `ShyamRuntime` starting before sovereign components and transitioning to `READY` when they become online.
- `test_runtime_repeated_lifecycle`: Tests multiple consecutive start/stop cycles of `ShyamRuntime` to ensure idempotency and zero task leaks.
- `test_runtime_standalone_mode_without_external_components`: Tests `ShyamRuntime` running with Zarya/Flux disabled, verifying standalone `READY` state.
