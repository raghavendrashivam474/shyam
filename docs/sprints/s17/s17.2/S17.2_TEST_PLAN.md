**Sprint:** S17.2 — Cross-Node Provider Transport Integration

**Baseline:** v0.17.1 (Commit 6366865)
**Target:** v0.17.2
**Status:** Executed & Verified

---

## 1. Executive Summary

This test plan defines the testing strategy, test matrix, and verification criteria for completing the provider-side transport integration in Shyam S17.2.

S17.2 bridges the three gaps identified during S17.1 multi-node validation:
1. **Target transport metadata extraction** from S9 candidate resolution into S16 ContinuityTarget.
2. **Shyam Node ID to Flux Peer ID mapping** for artifact transfer.
3. **Zarya target-aware routing** for remote work continuation without mutating local daemon bindings.

## 4. Regression & Boundary Isolation Criteria

1. **Zero Breaking Changes to S8–S16 Boundaries**:
   - NavigationConstraints and NavigationRequest models remain generic and provider-agnostic.
   - S13 trust model TrustRecord and verification logic are untouched.
   - S16 state machine transitions (ContinuityState) and terminal states remain strict.
2. **Backward Compatibility**:
   - ContinuityTarget transport fields (Flux_peer_id, zarya_url) default to None for purely local operations.
   - ZaryaProvider.continue_work preserves optional 	arget_url parameter defaulting to None.
3. **Pass Criteria**:
   - 100% of baseline unit and integration tests (392 tests) must pass with zero modifications to core business logic assertions.
   - All 6 new integration tests in 	ests/integration/test_s17_2_provider_transport.py must pass cleanly.
