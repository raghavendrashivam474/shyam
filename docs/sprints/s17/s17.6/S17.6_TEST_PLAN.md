## 1. Test Strategy

|-------|------|-------|-------|

## 2. Unit Tests (`tests/unit/test_surface.py`)

### 2.1 `test_intent_parser_matching`
**Purpose:** Verify deterministic keyword matching for the first vertical slice.

**Cases:**
- `"continue this work on my other laptop"` → `CONTINUE_WORK`
- `"resume task on computer"` → `CONTINUE_WORK`
- `"transfer project to machine"` → `CONTINUE_WORK`
- `"move this to my other laptop"` → `CONTINUE_WORK`
- `"pick up work on tablet"` → `CONTINUE_WORK` (multi-word signal)
- `"what is the weather today?"` → `UNKNOWN`
- `""` → `UNKNOWN`
- `"   "` → `UNKNOWN`

**Key detail:** Parser uses substring matching (not split-word) to handle
multi-word signals like `"pick up"`.

### 2.2 `test_presenter_messages`
**Purpose:** Verify human-friendly message generation for all readiness states
and continuity outcomes.

**Cases:**
- `EcosystemReadiness.READY` → contains "ready"
- `EcosystemReadiness.STARTING` → contains "getting things ready"
- `EcosystemReadiness.DEGRADED` → contains "unavailable"
- `success_response()` → state=COMPLETED, contains "done"
- `executing_response()` → state=EXECUTING
- `failure_response("details")` → state=FAILED, detail preserved

### 2.3 `test_input_adapters`
**Purpose:** Verify that text and voice adapters produce correctly tagged
`InteractionRequest` objects.

**Cases:**
- `TextInputAdapter.create_request("hello")` → source="text"
- `VoiceInputAdapter.create_request_from_transcription("voice")` → source="voice"

### 2.4 `test_voice_adapter_stt_transcription`
**Purpose:** Verify async STT hook integration.

**Cases:**
- `VoiceInputAdapter(stt_transcriber=fake_stt).transcribe_and_create(b"12345")`
  → text="transcribed 5 bytes", source="voice"

## 3. Integration Tests (`tests/integration/test_surface_coordinator.py`)

### Fixture
All integration tests use a `runtime_settings` fixture that creates a
`ShyamSettings` with `zarya_enabled=False`, `flux_enabled=False`,
`discovery_enabled=False`, and a temp `data_directory`.

### 3.1 `test_coordinator_degraded_when_runtime_not_ready`
**Purpose:** Verify that the surface returns a degraded response when the
ecosystem is not ready, without attempting continuity.

**Method:**
1. Create `ShyamRuntime` with disabled providers.
2. Start `SurfaceCoordinator`.
3. Send `"continue this work on my other laptop"`.
4. Assert response state=DEGRADED, message contains "ready".

### 3.2 `test_coordinator_unknown_intent`
**Purpose:** Verify graceful handling of unrecognised input.

**Method:**
1. Create runtime, start coordinator.
2. Override `runtime.readiness_tracker._readiness = EcosystemReadiness.READY`.
3. Send `"tell me a joke"`.
4. Assert response state=IDLE, message contains "not sure".

**Key detail:** Uses direct `_readiness` attribute override because the
`readiness` property is read-only (no setter/deleter).

### 3.3 `test_coordinator_continuity_success`
**Purpose:** Verify end-to-end continuity delegation on success.

**Method:**
1. Create runtime, inject mock `ContinuityService`.
2. Mock returns `ContinuityResult(outcome=SUCCESS)`.
3. Override readiness to READY.
4. Send `"continue this work on my other laptop"`.
5. Assert state=COMPLETED, message contains "done".
6. Assert `request_continuity` was awaited exactly once.

### 3.4 `test_coordinator_continuity_failure_handling`
**Purpose:** Verify human-friendly error translation on continuity failure.

**Method:**
1. Mock continuity returns `ContinuityOutcome.FAILED`.
2. Assert state=FAILED, message contains "couldn't continue".
3. Internal detail preserved in `response.detail`.

### 3.5 `test_coordinator_readiness_event_reaction`
**Purpose:** Verify event-driven state updates without polling.

**Method:**
1. Start coordinator (initial state=DEGRADED).
2. Publish `EcosystemReadinessChangedEvent(STARTING → READY)`.
3. Assert `coordinator.current_state == SurfaceState.IDLE`.

  `src/shyam/navigation/`, `src/shyam/providers/`, or `src/shyam/context/`.

## 5. Edge Cases Covered

| Edge Case | Test |
|-----------|------|
| Empty input | `test_intent_parser_matching` |
| Whitespace-only input | `test_intent_parser_matching` |
| Multi-word signal ("pick up") | `test_intent_parser_matching` |
| Runtime not ready | `test_coordinator_degraded_when_runtime_not_ready` |
| Continuity service unavailable | `test_coordinator_continuity_success` (mock) |
| Readiness state transitions | `test_coordinator_readiness_event_reaction` |
| Async STT transcription | `test_voice_adapter_stt_transcription` |

---

## 6. What Is NOT Tested in S17.6

- Real voice/audio capture (no microphone hardware in CI).
- Real cross-device continuity (requires S17.4 physical setup).
- Full interactive CLI loop (manual validation only).
- LLM-based intent parsing (not implemented; deterministic only).

These will be addressed in S17.7+.
